# Alloy migration notes

This branch is the starting point for moving Artemis away from `ethers-rs` and toward Alloy for QuickNode / AgentCash-backed on-chain arbitrage experiments.

## Baseline result

The repository is still strongly coupled to `ethers-rs`:

- Workspace dependencies define `ethers = "2"` and `ethers-signers = "2.0"`.
- Core collectors and executors use `ethers::providers::Middleware`, `PubsubClient`, and `ethers::types`.
- Flashbots / MEV-Share integrations currently depend on `ethers-flashbots` and `mev-share`, both of which are ethers-oriented.
- Contract bindings under `crates/strategies/*/bindings` were generated by `ethers-rs` Abigen and contain the majority of direct `ethers::` references.

That means a real Alloy upgrade is needed before this is a clean modern base for new arbitrage work.

## Build baseline established

Before replacing APIs, this branch makes the existing project buildable on current Rust by refreshing the stale `wasm-bindgen` lockfile entries. Without that, `cargo test --all` fails before we can safely refactor.

Verified with:

```sh
cargo test --all
```

Environment prerequisites used for the baseline test:

- Rust `1.96.0`
- Foundry / Anvil `1.7.1`
- system packages: `pkg-config`, `libssl-dev`

## Proposed migration order

1. **Provider and primitive boundary**
   - Introduce Alloy dependencies at the workspace root (`alloy`, or narrower `alloy-primitives`, `alloy-provider`, `alloy-rpc-types-eth`, `alloy-signer*` crates depending on final API choices).
   - Add a small internal compatibility module for common primitive conversions while old ethers bindings still exist.

2. **Core collectors**
   - Migrate `block_collector`, `log_collector`, and `mempool_collector` from `ethers::providers::Middleware` to Alloy providers/subscriptions.
   - Keep the `Collector` trait shape stable so strategies can migrate independently.

3. **Mempool executor**
   - Replace `SubmitTxToMempool` and raw transaction submission with Alloy transaction request / provider APIs.
   - This is the piece most directly needed for QuickNode RPC usage.

4. **Generated contract bindings**
   - Regenerate bindings with Alloy `sol!` / contract binding tooling instead of ethers Abigen.
   - Do this strategy-by-strategy; the generated bindings account for most of the migration surface.

5. **MEV-Share / Flashbots / builder integrations**
   - Replace or wrap ethers-specific `mev-share` and `ethers-flashbots` usage.
   - For on-chain arb experiments, prefer a minimal Alloy-compatible path first: observe data, simulate, and submit through QuickNode/private relay endpoints.

6. **AgentCash integration layer**
   - Keep AgentCash as a runtime/service integration rather than a low-level chain primitive.
   - Add it after the provider/executor boundary is Alloy-based, so paid APIs can feed opportunities into strategies without contaminating core chain types.
